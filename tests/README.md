# Validation

Current account and world smoke commands use verified TLS and account-owned characters. See [account acceptance checks](../docs/operations/accounts.md#verification). Earlier feature-specific native scripts still have legacy JSON fixture setup.

See the [Skills and Combat UI v0.2 validation report](../docs/architecture/skills-v02-validation.md) for the per-class scenarios and the disconnect-before-acknowledgement test.

Combat animation checks compile three pure presentation decision files into this harness without referencing the native game assembly. They verify clip coverage, timestamped casting, hurt/interrupt behavior, stale snapshots, deduplicated projectile travel, defense expiry/disconnect, authoritative mobility anchors and death/respawn. The harness includes the v0.2 skill tree, hotbar, weapon and scroll checks. Native smoke also compares effect sequences and checks projectile displacement, aura expiry and animated states. `tools/capture-combat.ps1` exercises all three classes, pixel targeting and cleanup, saving screenshots to ignored artifacts.

Economy checks cover package references/probabilities, equipment restrictions and swaps, exact identities/metadata, armor healing/clamping, all three classes' ranked damage with defense, combat locks, save migration/failure/restart, once-per-life reachable drops, contribution ties, EXP conservation, protection/public/expiry, pickup capacity/replays, all six recipes, cross-stack ingredients, exact scroll consumption, full bags and shared-input races. `tools/smoke-economy.ps1 -Capture` launches two real clients, seeds only isolated offline fixture saves, then uses normal UI and RPCs for crafting/equipment and natural combat for loot. It compares replicated drop state/removal, races public pickup, rejects protected/full-bag pickup, checks durable acknowledgements, and restores exact ownership and receipts through reconnect and restart.

Inventory checks cover empty/default capacity, catalog validation, partial-stack insertion, overflow/full rollback, move/swap/split/merge, equipment/metadata compatibility, atomic multi-stack and multi-item removal/exchange, retained identities, deterministic sort, immutable snapshots, trusted reward/removal deduplication, stale revisions beyond the client receipt window, concurrent preparations/serialized commits, ownership isolation, metadata persistence, old-save migration, one-time kits, corrupt saves and concurrent stale-write protection. `tools/smoke-inventory.ps1 -Capture` drives native mouse drag/drop and controls on two Godot clients, checks durable acknowledgements and exact reconnect/restart restoration, and saves the UI at two window sizes.

Progression checks cover exact thresholds, overflow/cap, point conservation, all twelve rank tables, level gates, stale/replayed upgrades, frozen in-flight casts, actual ranked damage/mobility/interrupt/defense behavior, effective contribution limits, kill budgets, eligibility/window/distance, penalties, duplicate lives, natural monster kills, PvP exclusion, stable identity and repository restarts/corruption/rollback/writer exclusion. File repository tests use isolated temporary directories. `tools/smoke-progression.ps1` adds two real clients, shared natural kills, owner updates, upgrades, reconnect and a full server restart; `-Capture` tests rendered UI and keyboard controls at 1280×720 and 1920×1080 windows.

`Arvenok.Tests` is a dependency-free executable regression harness. Run it with `dotnet run --project tests/Arvenok.Tests`; it returns a nonzero status if any check fails. It tests observable simulation and configuration behavior with explicit time steps and no engine, network, wall clock or sleep. It is intentionally not registered with `dotnet test`.

`tools/validate.ps1` runs architecture and Woodvale asset checks, locked restore, the full build and this harness. Tests cover all six class pairings, navigation, swept mobility, safe-zone boundaries, cast cancellation, interrupt timing, range/line of sight at completion, simultaneous lethal hits, multiple attackers, defense, death/respawn, duplicate/stale/rate-limited input, disconnect/reconnect and JSON snapshot round trips. Forest checks cover preserved landmarks, water/shore blocking, prop footprints, monster spawn validity, 1-3 second idle periods, two minutes of bounded/collision-safe wandering, repeatability, empty-world continuity and the shared PvE pipeline.

`tools/smoke-game.ps1` drives an actual Godot server and two scripted ENet clients through safe-zone rejection, movement, class choice, a duplicate cast, an interrupt, defense, damage, death and protected respawn. It also confirms art loads and monster motion, compares monster position/facing/state/HP hashes at common authoritative revisions, and reconnects new clients to check monster IDs persist. Oversized unreliable-packet warnings fail the check. These are rule/integration checks, not human gameplay or balance verification. For future service/data work add isolated integration tests, protocol compatibility fixtures and measured load/soak workloads. Choose a standard test runner when suites need richer discovery/reporting.
